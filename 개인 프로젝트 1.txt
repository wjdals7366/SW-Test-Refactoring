부하 테스트: 1만 건 DB 갱신 요청으로 병렬 처리 성능 검증
기능 검증: 이용권 차감, 강사 시간표 변경, 사용자 등록이 병렬로 수행되면서도 정상 처리되는지 확인
예외 처리 검증: 각 동작별 예외처리로 오류 없이 수행되는지 확인
경계값/제약조건 검증: 시간 겹치는 예약이 실제로 차단되는지 확인 (일종의 네거티브 테스트)
모니터링/데이터 정합성 검증: 통계 그래프와 DB 값이 일치하는지 확인

- Spring Batch 부하 테스트
- 기능검증 테스트

추가 테스트

- 경계값 / 제약조건 검증
- 모니터랑 / 데이터 정합성 검증

용어 정리
VU (Virtual User) : 가상의 접속자 1명. 
ex) VU = 10 -> 10명 동시접속을 의미
Latency : 요청 후 응답까지 걸린 시간
Throughput : 초당 일 처리 수 (RPS, requests per second)
iterations : 총 테스팅 시도 횟수
duration : 테스트 진행 시간
maxDuration : 최대 응답 대기시간
avg : 평균응답시간
min : 최소응답시간
max : 최대응답시간

탐색적 테스팅 중 발견된 보완점
- user의 password가 encrypt 되지 않음
- dashboard 접속 시 Whitelabel Error page (400 bad request) 발생
원인 : URL에 별도 파라미터 없이 접속하면 발생

해결

@GetMapping
public ModelAndView home(ModelAndView modelAndView, @RequestParam("to") String toString) {
    LocalDateTime to = LocalDateTimeUtils.parseDate(toString);

위 구문에서 쿼리 파라미터 없이 /admin으로 접속하면 400 bad request 발생
@RequestParam의 기본 값이 required = true 라서, 통계 차트 조회 기준일 to를 클라이언트가 반드시 넘겨줘야 하는 구조였음
dashboard 진입점이 외부 파라미터에 의존하는 설계기 때문에 URL을 정확히 모르면 아예 접근이 불가능한 UX 결함

@GetMapping
public ModelAndView home(ModelAndView modelAndView, @RequestParam(value = "to", required = false) String toString) {
    LocalDateTime to = (toString == null) ? LocalDateTime.now() : LocalDateTimeUtils.parseDate(toString);

변경점
1) required = true 를 1) required = false 로 변경해 파라미터 부재를 허용
2) toString이 없을 경우 LocalDateTime.now() 를 기본 기준일로 적용

개선 효과
1) /admin 만 입력해도 대시보드가 즉시 랜더링 됨 (UX 결함인 URL진입장벽 제거)
2) 기존기능 (날짜기준조회)은 그대로 유지 - 하위 호환성 보존
3) 사용자가 날짜를 입력하지 않더라도 오늘 기준의 통계를 보여주는 관리자 도구로서의 사용경험 개선
